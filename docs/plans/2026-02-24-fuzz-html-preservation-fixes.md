# Fuzz Analysis: Formatting Preserves Asciidoctor HTML Output

1000 runs, 100% failure rate, ~783 unique counterexamples.

## Data Source

Generated by
`bun scripts/fuzz-batch.ts "formatting preserves Asciidoctor HTML output"`. Raw
results in `/tmp/fuzz-results/` (1000 `.txt` + `.seed` files).

The test asserts
`normalizeHtml(convertToHtml(format(input))) === normalizeHtml(convertToHtml(input))`
— formatting should not change the HTML that Asciidoctor produces, ignoring
whitespace-only differences in text nodes (see "Resolved: RC1" below).

## Resolved: Newline-to-space collapsing in paragraphs

Asciidoctor preserves source newlines within paragraph text in its HTML output
(`<p>word1\nword2</p>`), but the formatter reflows lines (`<p>word1 word2</p>`).
These render identically in browsers.

This is not a formatter bug — Asciidoctor has no option to collapse text-node
whitespace; it simply passes source whitespace through. The test now normalizes
`\n` → ` ` outside `<pre>` blocks before comparing (`normalizeHtml()` in
`tests/format/fuzz.test.ts`).

## Root Causes

All remaining failures are real semantic bugs in the formatter. The failure rate
is still 100% because these bugs are pervasive enough to affect essentially
every generated input.

### RC1: Backtick fence → native listing conversion

> **Cross-reference:** The backtick → listing conversion also appears as **RC2
> sub-mechanism A** in `2026-02-24-fuzz-idempotency-fixes.md`, where the gap
> between `[source,lang]` and `----` causes an idempotency failure. Fixing this
> conversion eliminates that sub-mechanism too.

~42 unique counterexamples involve ` ``` `.

The formatter converts backtick-fenced code blocks to native AsciiDoc listing
blocks (`----`). Asciidoctor produces different HTML for each:

````
```code```  →  <pre class="highlight"><code>code</code></pre>
----/code/----  →  <pre>code</pre>
````

The `<code>` wrapper and `highlight` class are lost. This is a semantic change
that affects syntax highlighting behavior.

**Examples:**

- `"```"` → `"----\n----\n"`
- `"```\ntext {a} here"` → native listing with different HTML

### RC2: Literal `+` escaping

~8 unique counterexamples.

The formatter escapes bare `+` as `\+` to prevent it from being parsed as an
inline passthrough delimiter. But Asciidoctor renders `\+` literally (with the
backslash visible), not as `+`:

```
"+"           →  <p>+</p>
"\+"          →  <p>\+</p>
```

Same issue inside inline formatting: `` `+` `` → `` `\+` ``.

### RC3: Definition list formatting

~22 unique counterexamples.

The formatter changes the structure of definition list entries, causing
Asciidoctor to parse them differently:

```
":a:: "      →  <dl><dt>:a</dt></dl>
":a:\n\n:\n" →  <p>:</p>
```

The reformatted output is no longer recognized as a definition list.

### RC4: Block separation changes

> **Cross-reference:** This is the same underlying bug as **RC2 (Missing blank
> line separators between blocks)** in `2026-02-24-fuzz-idempotency-fixes.md`.
> Both point to `joinBlocks()` in `src/print-join.ts`. Fixing block separation
> addresses both plans.

A subset of multi-line counterexamples where the formatter inserts a blank line
that changes block structure. For example:

```
"some *x* text\n<1> item"
```

Formatted to `"some *x* text\n\n<1> item\n"` — the inserted blank line causes
`<1> item` to be parsed as a callout list (separate block) instead of paragraph
text. This changes the HTML from a single `<p>` to a paragraph +
`<ol class="colist">`.

Similar cases with `=  ` (incomplete headings), block delimiters, and block
macros that get separated by blank lines.

## Verification

After each fix, re-run
`bun scripts/fuzz-batch.ts "formatting preserves Asciidoctor HTML output"` and
compare failure rates.

- **Baseline:** 1000/1000 failures, ~783 unique counterexamples
- **After RC1 (backtick fence):** backtick examples should disappear
- **After RC2 (`+` escaping):** `+`-related examples should disappear
- **After RC3 (definition lists):** `::` examples should disappear
- **After RC4 (block separation):** remaining structural changes should drop

Target: 0/1000 failures.
